## Q1. Teacher + date for each CURRENT Threnody source (pass/fail on the June-2026+ rule)

### Takeaway
Every one of the nine current sources FAILS the rule: all were generated by teachers released in 2024-2025 (Claude 3.7 Sonnet, GLM-4.6, DeepSeek-V3.2, Qwen3-235B, Qwen3-32B, etc.) or the teacher is undisclosed and the dataset itself predates June 2026. The whole current mix must be replaced.

### Inferences
- Nemotron-SFT-SWE-v3 is very likely the MiniMax-M2.5 + Qwen3-Coder-480B corpus described in the Nemotron 3 Ultra report (tag `Nemotron_3_Ultra`, same harnesses), so treat it as FAIL. This link is not stated on the card.

- For Threnody (CLI harness, Qwen3.5-9B student), the strongest fit is Open-SWE-Traces v2.0/v1.2 `claudecode` and `opencode` splits filtered to `resolved == 1`: CLI-native harnesses, 2026 teachers, permissive licensing, per-row repo license. A 9B student will need context-length filtering (token stats not published on the card).
- LegoFlow-SWE has the best reported SFT efficiency (1k samples → 70.2 Verified on a 35B-A3B student) but its 130k-token average trajectories are very long for a 9B model and it lacks a license — contact Lego-X before use.

## Q3. 2026 verifiable task environments runnable WITHOUT Docker (pure Python subprocess)

### Takeaway
Almost every 2026 environment set (SWE-rebench-V2, LegoFlow-SWE, Terminal-Lego, Recursive-Task-Synthesis, Repo2RLEnv, TMax) is Docker/Harbor-based. Truly Docker-free sets are tiny (noodcon's 4-instance SWE-DockerLess / TerminalBench-DockerLess) or simulated (SWE-World). Practical route: take Python-only tasks from Docker sets (SWE-rebench-V2 Python subset, SWE-Lego-Real-Data, LegoFlow-SWE Python tasks, SWE-smith) and rebuild them as venv + `git apply` + pytest, following the SWE-DockerLess recipe.

### Cited Findings
- noodcon/SWE-DockerLess (2026-10-31, MIT): SWE-bench-compatible rows that need "no Docker, no network and no prebuilt image"; each row carries a repo snapshot, reproduced via temp dir, `git init`, `git apply`, pytest — but only 4 instances (29 F2P / 67 P2P tests). — [HF card](https://huggingface.co/datasets/noodcon/SWE-DockerLess)
- noodcon/TerminalBench-DockerLess (2026-10-31, MIT): Terminal-Bench task model with the image replaced by a setup script; needs only bash, git, python; 4 tasks. — [HF card](https://huggingface.co/datasets/noodcon/TerminalBench-DockerLess)
- SWE-World (arXiv 2602.03419, Feb 2026, EMNLP 2026 Findings) replaces execution with a learned surrogate model (16.6K instances, 3,763 repos) — Docker-free but nothing actually runs. — [arXiv](https://arxiv.org/abs/2602.03419)
- laion published "rootless-apptainer" variants (e.g., laion/swegym-1k-rootless-apptainer, laion/endless-terminals-rootless-apptainer, laion/nemotron-terminal-easy-clean1k-rootless-apptainer, 2026-09-23/24) — no Docker daemon, but still container images (Apptainer). — [HF author listing](https://huggingface.co/api/datasets?author=laion&sort=createdAt&direction=-1)
- open-athena converted Recursive-Task-Synthesis Dockerfiles "into setup scripts replayed in fresh containers sharing a minimal base image" — reduces image builds but still containerized. — [HF card](https://huggingface.co/datasets/open-athena/recursive-task-synthesis-glm-5.3-rollouts)
- Docker-based 2026 task pools with Python subsets usable for venv conversion: nebius/SWE-rebench-V2 (CC-BY-4.0); PrimeIntellect/SWE-rebench-V2-Filtered-Verified (2026-04-28); PrimeIntellect/SWE-Lego-Real-Data (4,432 Python tasks, Apache-2.0, pytest F2P/P2P IDs cleaned); Lego-X/LegoFlow-SWE (716 Python tasks of 5,000); Lego-X/Terminal-Lego-15k (Apache-2.0); FineEnvs/repo2rlenv-swe-smith (100 Harbor tasks). — [SWE-Lego-Real-Data](https://huggingface.co/datasets/PrimeIntellect/SWE-Lego-Real-Data); [LegoFlow-SWE](https://huggingface.co/datasets/Lego-X/LegoFlow-SWE); [Repo2RLEnv](https://huggingface.co/datasets/FineEnvs/repo2rlenv-swe-smith)
- SWE-bench's official FAQ states evaluation without Docker is not supported. — [SWE-bench FAQ](https://www.swebench.com/SWE-bench/faq/)

### Inferences
- PrimeIntellect/SWE-Lego-Real-Data is the best seed for a venv-based harness: Python-only, Apache-2.0, already cleaned of un-collectable pytest IDs; pair it with a June-2026+ teacher (Qwen3.8-27B Apache-2.0 or GLM-5.2 MIT) to generate Threnody's own trajectories.
- Threnody's existing AgentLoop eval (pure Python subprocess) could reuse the SWE-DockerLess row schema (snapshot + test command) for self-generated tasks.

### Gaps
- No 2026 large-scale (>100 task) dataset of real-repo tasks pre-packaged for venv/pip execution was found.

## Q4. Licensing of distillation from 2026 open-weight teachers

### Takeaway
Cleanest teachers for Apache-2.0 redistribution: **Qwen3.8-27B (Apache-2.0)**, **GLM-5.2 (MIT)**, **DeepSeek-V4-Flash-0731 / V4.1-Flash (MIT)**. Kimi-K3 and GLM-5.3 use modified-MIT licenses with commercial "Model as a Service" conditions; Qwen3.8-Flash-Next uses the new Qwen Community License 1.0 (MaaS and "AI Work Assistant" carve-out — directly relevant to an agentic coding model); MiniMax-M3 is non-commercial by default. None of these license texts explicitly forbids training other models on outputs, but the derivative-work clauses are ambiguous for distilled models.

### Cited Findings
- Qwen/Qwen3.8-27B: license tag Apache-2.0 (createdAt 2026-08-05). — [HF API](https://huggingface.co/api/models/Qwen/Qwen3.8-27B)
- Qwen/Qwen3.8-Flash-Next: "Qwen Community License 1.0". Grants rights to "use, copy, modify ... fine-tune, and create derivative works"; if the licensee "conducts a Model as a Service or AI Work Assistant business", it must "obtain a separate license from Qwen before Using the Software or its derivative works for any commercial purpose"; "AI Work Assistant" is defined as an independent product "primarily designed for AI-assisted coding or office productivity"; >100M MAU or >US$20M monthly revenue must display the model name. — [LICENSE](https://huggingface.co/Qwen/Qwen3.8-Flash-Next/blob/main/LICENSE)
- Kimi-K3 ("Kimi K3 License", modified MIT): permits use, fine-tune, derivative works; MaaS operators above US$20M revenue over 12 months need a separate agreement for commercial use; products >100M MAU or >US$20M monthly revenue must display "Kimi K3"; output is covered only by an "AS IS" warranty disclaimer. — [LICENSE](https://huggingface.co/moonshotai/Kimi-K3/blob/main/LICENSE)
- GLM-5.3 ("GLM-5.3 License", modified MIT): broad MIT-style grant; MaaS businesses with >US$10 billion revenue must pass Z.AI security review before commercial use. GLM-5.2, GLM-5.1, GLM-5, GLM-4.7 are tagged MIT. — [GLM-5.3 LICENSE](https://huggingface.co/zai-org/GLM-5.3/blob/main/LICENSE); [GLM-5.2 API](https://huggingface.co/api/models/zai-org/GLM-5.2)
- MiniMax-M3 ("MiniMax Community License"): grant is "for non-commercial purposes"; commercial use requires "Built with MiniMax M3" attribution plus a one-time notice to MiniMax (or prior written authorization above US$20M yearly revenue); "Commercial Use" explicitly includes deploying derivatives "subjected to post-training, fine-tuning ... or any other form of modification"; includes a prohibited-use appendix (e.g., military). — [LICENSE](https://huggingface.co/MiniMaxAI/MiniMax-M3/blob/main/LICENSE)
- DeepSeek-V4-Pro, DeepSeek-V4.1-Flash, DeepSeek-V3.2: MIT license tag. — [V4.1-Flash API](https://huggingface.co/api/models/deepseek-ai/DeepSeek-V4.1-Flash); [V4-Pro API](https://huggingface.co/api/models/deepseek-ai/DeepSeek-V4-Pro)
- Dataset-level licenses for passing candidates: nvidia/Open-SWE-Traces CC-BY-4.0 ("ready for commercial/non-commercial use"); nvidia/Nemotron-SFT-Agentic-v4 OpenMDW-1.1; marin GLM-5.2 code set OpenMDW-1.1; open-athena GLM-5.3 traces "other"; Lego-X/LegoFlow-SWE none declared. — [Open-SWE-Traces](https://huggingface.co/datasets/nvidia/Open-SWE-Traces); [Agentic-v4](https://huggingface.co/datasets/nvidia/Nemotron-SFT-Agentic-v4); [LegoFlow-SWE](https://huggingface.co/datasets/Lego-X/LegoFlow-SWE)

### Inferences
- Whether a model distilled from teacher outputs is a "derivative work" of the teacher is not defined in any of these licenses; Apache-2.0/MIT teachers (Qwen3.8-27B, GLM-5.2, DeepSeek V4.x) carry the least risk for an Apache-2.0 Threnody release.
- Qwen3.8-Flash-Next-generated data (Open-SWE-Traces v2.0) is the most license-sensitive passing source because Threnody is itself an AI coding model; if risk-averse, prefer v1.2 (Qwen3.8-27B, Apache-2.0) over v2.0. NVIDIA's CC-BY-4.0 on the dataset does not override upstream model terms (Open-SWE-Traces card: users are responsible for checking applicable licenses).
- MiniMax-M3-generated data is the riskiest for a commercial Apache release (non-commercial default grant, post-training clause).

### Gaps
- I did not read the DeepSeek-V4-Flash-0731 LICENSE file separately or any separate terms-of-use for API-served (as opposed to open-weight) teacher outputs; Kimi K3 via OpenRouter (used by some community sets) may carry API ToS terms not covered here.
- No legal commentary specific to 2026 distillation of these licenses was found; this is a reading of the license texts, not legal advice.
